ALMa v0.24.2

This patch restores Feed monitoring after transient failures, prevents author
batch limits from hiding recent works, and preserves refresh timing across
restarts. It also includes the hydration and interrupted-job fixes already on main.

## Fixed

- Failed author monitors remain eligible for the next refresh. A temporary DNS
  error or timeout no longer stops an author monitor indefinitely.
- Authors hidden by a shared batch result cap receive bounded follow-up queries.
  Coauthored works from another batch no longer displace an author's newer papers.
- Feed auto-refresh keeps its due time across process restarts and catches up
  when overdue, while retaining its opt-in and network admission controls.
- Activity reports failed refreshes and repeated zero yield. Monitor diagnostics
  distinguish existing Feed rows, dismissals, components and invalid candidates.
  Request errors are redacted, and single-monitor setup releases its database
  transaction before network calls.
- Transient author hydration failures retry after six hours rather than thirty
  days. Papers fetched through Scholar enter the shared metadata hydration queue.
- Interrupted background jobs consume their old resume marker after a replacement
  is scheduled, preventing repeated relaunches across restarts.

## Development

The local backend test runner selects affected components and runs isolated
processes. Backend tests remain in their separate local repository.

## Notes

The Feed's 60-day view and dismissal behavior are preserved. No unrelated feature
branch work is included in this release.
