# ALMa v0.25.1

Fixes for two problems v0.25.0 brought to phones and PDFs.

## Fixed

- **White page after an upgrade, mostly on iPhone.** `index.html` carried no
  caching rule, so a browser could keep the old page and run the old app against
  the new API. It now revalidates on every load, and so do the other files that
  keep their name across releases.
- **Images and PDFs answered 500 to any browser that accepts gzip.** Compression
  dropped the start of the response for files it left alone. This hit the logo,
  the paper textures and the favicon, and PDFs read in the browser.
- **A page that fails to render now says so.** ALMa shows the error and a Reload
  button in place of a blank page.

## Changed

- `fastapi` and `starlette` are pinned, so the image runs the versions the tests
  ran.

## Upgrading

One phone step, this once: a phone holding the old page may need its site data
cleared, because the new caching rule cannot reach a page it never requests. On
iOS: Settings → Apps → Safari → Advanced → Website Data, then delete your ALMa
host. If ALMa is on your Home Screen, also remove it and add it again.
