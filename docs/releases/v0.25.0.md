ALMa v0.25.0

This release slims ALMa to a core of Feed, Discovery, Authors and Library, with
optional features behind switchable add-ons. Like and Love now only rate. Merges
of authors and papers hold, and can be undone. ALMa also refuses requests under
a name it does not know, so read the next section before you upgrade.

## Before you upgrade

- **Back up first. The upgrade is forward only.** The first start migrates the
  database from schema 45 to 58, with no way down. Use **Settings → Data &
  system → Library maintenance → Backup**, or
  `POST /api/v1/library-mgmt/backup`, and keep the snapshot with the image you
  are leaving. If Watchtower updates ALMa, do this before the release reaches
  it, because the migration runs unattended.

- **Newer databases refuse older images, from this release on.** A build that
  finds a schema newer than it knows stops at startup and changes nothing.
  Images up to 0.24.2 do not have this check: they log a warning, report healthy
  and run on a schema they do not know. Never start one on an upgraded database.
  Going back means [restoring the snapshot](../operations/backups.md#restore)
  together with the image that wrote it. If a fresh install or an Alerts Remove
  dropped `plugins.email.enabled` from `settings.json`, an older image fails
  startup until `"plugins.email.enabled": false` is added back.

- **ALMa refuses hostnames it does not know.** The `Host` header must be
  `localhost`, an IP address or an address listed in `ALMA_ALLOWED_ORIGINS` or
  `FRONTEND_URL`. Anything else gets `403` with `UnknownHostRefused`, reads
  included. Older images ignore the variable, so set it before upgrading.
  Watchtower keeps the settings a container already has, so a value added
  afterwards does not arrive. A malformed entry stops startup with an error that
  names it. See [Deployment](../operations/deployment.md).

- **A proxy must keep `Host`.** List the address you open and make the proxy pass
  on the `Host` the browser sent. Tailscale Serve does. nginx needs
  `proxy_set_header Host $host;`. Never list the proxy's upstream name:
  forwarded headers are not read, and listing that name reopens DNS rebinding.

- **Update the browser connector with ALMa.** It moves to contract 2. An older
  connector gets `400` on Like and Love with a message saying nothing changed,
  and its Add still works. The connector now needs Firefox 128.

- **The OpenAI provider is gone.** Migration 54 deletes the stored key for good,
  both `ai.openai_api_key` and `openai.api_key` in the secret store, so keep a
  copy if you want it. `ai.provider` falls back to your default and
  `embedding_model` to SPECTER2. OpenAI vectors stay as rows nothing reads;
  **Delete Inactive** in the AI section removes them. SPECTER2 vectors are not
  touched.

- **Paper merging stays off until you run it.** Migration 58 turns off a stored
  automatic Reconcile, and Reconcile no longer defaults to on, because the wider
  same-work rules would otherwise merge hundreds of rows in an existing corpus
  on deploy. Only a row new to the corpus merges at ingest. After a backup, read
  the list from `python -m alma.services.merge_repairs --db <path> --list
  repairs.csv`, then run it with `--apply`. In the container the database is
  `/app/data/scholar.db`. Health can opt back in afterwards.

## Changed

- **Like and Love rate only, on every surface.** They set 4 and 5 stars where
  the paper stands. Only Save adds it to the Library, and an Inbox paper stays
  in the Inbox until you Save it or choose Not now. A rated paper still teaches
  Discovery and is not proposed again. Papers you already saved stay saved.

- **Alerts and the Auto tagger are add-ons.** Switch them in **Settings →
  Add-ons**. They turn off on an install that does not use them: Alerts with no
  rules or digests, the Auto tagger with no stored suggestions. Installs that do
  use them stay on. Off keeps the data and answers `404` on their routes. Remove
  takes a backup, then deletes their tables, settings and credentials. Email
  shows under Plugins only while Alerts is on. Tags and tag merging stay in the
  core.

- **One list view per surface.** The Library is a table, with Like, Love and
  Discover similar on its rows. Feed and Discovery lose Compact, Normal and
  Extended, and the Library loses its card view. Discovery's long provenance now
  opens with Why.

- **Slack and Email Check no longer send anything.** Slack asks about the token
  and channels, and Email logs in to the server. Delivery is proven by the first
  real digest. Settings, Home and Health now read one status per connection, and
  saved never reads as working.

- **The JSON export leaves Activity history out.** `/backup/export` remains the
  restorable database snapshot and still holds it.

- **Restore is offline only.** The restore route and button are gone. A running
  ALMa cannot safely replace its own database.

- **Health answers `503`** when the database or the scheduler has failed, and
  reports a `scheduler` field. Anything that watches that route will notice.

- **One Compose path.** `docker-compose.yml` now pulls a release, and `setup.sh`,
  `setup.ps1` and `scripts/deploy-prod.sh` are front ends to it. Local builds
  moved to `docker-compose.build.yml`, and `docker-compose.ghcr.yml` is gone.
  Volume names are unchanged.

- **Removed from the app:** the Health alert scorecard, trends and automation
  suggestions, XP, levels, streaks and daily challenges, channel yield, the
  shadow ranker, the legacy recommendation generator, the `alma` console script
  and 22 settings that did nothing.

## Removed routes

Nothing in the app calls these. There is no generic way to trigger a job any
more: use the action that owns the work.

- Scheduler: `GET /scheduler/status`, `POST /scheduler/trigger/{job_id}`
- Topics, now under `/library/topics`: `GET /topics`, `GET /topics/{id}`,
  `POST /topics/{id}/merge`, `POST /topics/dedup`, `POST /topics/dedup/dry-run`
- Papers: `PUT /papers/{id}/rate`, `POST /papers/dedup-preprints`,
  `POST /papers/rehydrate-metadata`, `GET /papers/enrichment-status`
- Authors: `GET /authors/{id}`, `GET /authors/{id}/dossier`,
  `PATCH /authors/{id}/type`, `POST /authors/{id}/confirm-openalex`,
  `POST /authors/{id}/empty-cache`, `POST /authors/{id}/fetch-preview`,
  `POST /authors/{id}/preview/save`, `POST /authors/{id}/refresh-cache`,
  `POST /authors/dedup-by-orcid`, `GET /authors/enrichment-status`,
  `POST /authors/garbage-collect-orphans`, `POST /authors/rehydrate-metadata`,
  `POST /authors/resolve-openalex`, `POST /authors/suggestions/refresh-network`
- Discovery: `GET` and `DELETE /discovery/recommendations`,
  `POST /discovery/recommendations/{id}/seen`, `GET /discovery/channel-yield`,
  `GET /discovery/stats`, `POST /insights/discovery/branch-action`,
  `GET /lenses/{id}`, `GET /lenses/{id}/signals`
- Settings and AI: `GET /settings/openalex/status`,
  `GET /settings/semantic-scholar/status`, `GET /settings/test/openalex`,
  `GET /settings/test/scholar`, `GET /ai/dependencies`,
  `POST /ai/title-resolution-sweep`
- Other: `POST /library-mgmt/restore/{backup_name}`, `GET /inbox/status`,
  `GET /plugins/{id}`, `GET /alerts/{id}`,
  `DELETE /library/tags/assign/{paper_id}/{tag_id}`

`/ai/configure` no longer takes `openai_api_key`. `/bootstrap` gains `addons` and
drops `alerts`. New: `/addons`, `/settings/connections`, author merge history and
undo, and joining or re-allowing paper pairs. See the
[API reference](../reference/api.md).

## Added

- **Undo in the toast of every card action**, on every surface.
- **Author merges that hold.** A merge survives a later refresh, keeps Feed
  verdicts, and can be undone from the author panel. Monitors also ask for merged
  profiles. The dedup job no longer merges authors.
- **Paper merges with evidence.** One same-work ladder serves ingest, repair and
  the job, reads registered relations, and moves a kept PDF and what you did with
  the paper to the survivor. The paper popup can split, join and show versions, and a split stays
  split.
- **Stored Discovery branches** that keep their members across refreshes, with
  ended branches and rebuild shown.
- **Sort Discovery** by Suggested, Ranking or Date.
- **Needs attention on Authors:** every row has a way out, and a survivor can be
  swapped.
- **Onboarding state** now lives in the database.

## Fixed

- Foreground writes no longer stall behind long background work.
- A refresh keeps its finished lanes and names any it lost.
- A Save replaces the Dislike before it, and Added is the time you saved.
- Undo of a rating takes the verdict off Feed and Discovery rows, and so does bulk
  Clear Rating.
- Author Delete never removes a paper you have a claim on, and a followed author
  is never removed.
- Feed reports scheduled refreshes as the last refresh. Rows you judged outlive
  their author or monitor.
- Google Scholar is contacted only when a setting and the network allow it, and
  manual scraping is off by default.
- A body a route cannot parse gets `422`, not `500`. Pages refuse framing, other
  sites cannot write, and secrets are redacted in stored errors and logs.
- BibTeX export keeps values inside their fields, joins authors with `and`, and
  gives every paper a unique cite key.

## Data changes on first start

- Migration 47 clears ratings that only a legacy Dismiss wrote.
- Migrations 46, 49 and 50 store branches and carry v0.24.2 branch controls over.
- Migrations 48 and 52 delete settings nothing reads.
- Migration 51 closes the old Feed refresh window.
- Migration 53 restores followed authors left removed.
- Migration 55 removes phantom follows: authors marked followed with no follow
  behind them become background authors. Real follows are not touched.
- Migrations 56 and 57 add the merge ledger, split verdicts and paper relations.

## Notes

Apart from the changes above, your papers, ratings, collections, follows and
vectors carry over. The tables this release stops using stay in place, and a
later release drops them.
